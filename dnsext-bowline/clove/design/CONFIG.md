# clove: 設定の扱いの設計

clove が設定ファイルの誤りや矛盾をどう扱うかに関する設計書です。

## 原則

- 設定ファイルに書いたことは、書いたとおりに効かせます。
- 書いた設定を黙って無視しません。効かせられない設定は、起動を止めるか、警告を出します。
- 起動を止めるか警告にとどめるかは、次の 3 つに分けて決めます。

| 種類 | 扱い |
|---|---|
| 設定ファイルの中で、どう読んでも意味が通らないもの | 起動を止める |
| スイッチを切った状態で、細かい設定が残っているもの | 矛盾とはみなさない。スイッチを優先し、必要なら警告を出す |
| ゾーンのデータや、鍵ファイルなど実行中に変わるもの | 警告にとどめる |

## 設定ファイルを読む時期

- 設定ファイル（`clove.conf` と `tsig-file`）は、起動時にだけ読みます。
- SIGHUP は、ゾーンを起こし、ログのファイルを開き直すだけで、設定ファイルは読み直しません。
- そのため、設定ファイルの誤りは、起動を止めることで知らせます。
- 将来、設定ファイルの読み直しを入れるなら、誤りがあったときは止まらずに、古い設定のまま動き続けます。

## 起動を止めるもの

設定ファイルの中で、どう読んでも意味が通らないものです。

- 知らない設定の名前、同じ設定の重複。
- 存在しない鍵の名前を指す設定（`allow-transfer-key`、`allow-notify-key`、`source-key`、`notify-key`）。
  - TSIG を頼まれたゾーンを、黙って TSIG 無しで動かさないためです。
- `tsig-file` の誤り。
  - ファイルがあるのに読めない、最初の `key:` より前に設定がある、名前の無い鍵や同じ名前の鍵がある、知らないアルゴリズム、秘密が base64 でない。
- 同じゾーンの重複。
- 署名の設定の誤り。
  - 知らないアルゴリズム、KSK と ZSK でアルゴリズムが違う、RSA の鍵の長さが範囲の外。
  - `rrsig-lifetime` と `zsk-rollover-duration` の関係が成り立たない。
- `--insecure` を付けずに書いた、`--insecure` が要る設定（`spoof-*`、`signer`）。
  - わざと間違った応答を返す設定なので、うっかり本番で効かないようにするためです。

## 矛盾とはみなさないもの

スイッチを切った状態で、細かい設定が残っているものです。

- スイッチを切れば、それに付く細かい設定は効きません。スイッチを優先します。
  - 例：`allow-transfer: no` で `allow-transfer-addrs` や `allow-transfer-key` が書いてある。
- 細かい設定を消さずにスイッチだけを切れるので、一時的に止めたいときに便利です。
- 細かい設定が効いていないことは、起動時に警告で知らせます。
  - 例：ECDSA や ED25519 の鍵に、`ksk-size` や `zsk-size` を書いた（`checkKeySize`）。

## 警告にとどめるもの

ゾーンのデータや、実行中に変わるものです。

- データを 1 つ書き換えただけで、サーバ全体が止まるのは厳しすぎるからです。
- 例：
  - ゾーンの TTL が `zsk-rollover-duration` 以上（#316）。
  - `tsig-file` を、グループやほかの人が読める。

## 既定値

- 書かなかった設定は、既定値で埋めます。
- 矛盾かどうかは、既定値で埋めたあとの値で判断します。書いたかどうかは区別しません。
  - 例外は、既定値が「使わない」を表す値になっている設定です（`ksk-size` と `zsk-size` の 0 など）。
