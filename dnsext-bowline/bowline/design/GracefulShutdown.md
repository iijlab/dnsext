# bowline: graceful shutdown の設計

bowline が quit と reload のときに、受け付けた問い合わせをどう扱うかに関する設計書です。

## 目的

- クライアントが終わりを知らされる前に送った問い合わせには、古い世代か次の世代のどちらかが答えます。知らされた後に送る分は、クライアントが送り直します。
- 読んだ問い合わせには、止まる前に答えます。
- reload では、受け付けを途切れさせません。
- どちらでも、止まるまでの時間に上限を設けます。

例外は次の 2 つです（「停止したときの振る舞いの一覧」を参照）。

- QUIC の reload：1 つ目と 2 つ目が成り立ちません。答えずに CONNECTION_CLOSE を送り、クライアントが送り直します。
- UDP の quit：1 つ目が成り立ちません。停止から 100 ms を過ぎて届いた問い合わせには、クライアントが知らされないまま答えません。

終わりの知らせ方は、トランスポートごとに次のとおりです。

| トランスポート | 終わりの知らせ方 |
|---|---|
| UDP | 知らせる手段が無い |
| TCP、DoT | 接続を閉じる |
| DoH、H2C | GOAWAY を 2 回 |
| H3 | quit では GOAWAY を 2 回、reload では CONNECTION_CLOSE |
| DoQ | CONNECTION_CLOSE |

- UDP は知らせる手段が無いので、reload ではソケットごと次の世代に渡し、quit では停止の時点で届いていたものを読んでから答えます。

## 言葉

- **世代**：1 つの設定で動いている bowline の一揃い（サーバ、パイプライン、モニタ、Web API）。`runConfig` 1 回が 1 世代です。
- **停止**：世代に quit か reload の命令が来たこと。
- **pending の印**：読んだ問い合わせに付ける印。答えを送るか、答えないと決めたときに外します。

## 守ること

1. **2 つの世代が、同じソケットを同時に読まない。**
   - 古い世代は、全サーバに停止を伝え終えてから、ソケットを渡します（`Stopper` の `stopAll`）。
   - 伝える前に渡すと、古い世代が拾った接続は、答えずに閉じられます。
2. **pending の印は、問い合わせの処理がどう終わっても外す。**
   - 答えを送ったときのほか、答えずに処理を終えるとき（デコードできない、応答だった、worker で失敗した、例外が起きた）も外します。
   - 外し忘れると、VC のセッションは送信側が終わらず、idle timeout でも閉じず、quit と reload がそれを待ち続けます。
3. **読んだ問い合わせには答える。読む前のものは、渡せるなら次の世代に渡す。**
   - reload では、待ち受けソケットごと次の世代に渡るので、カーネルのバッファにあるものは失われません。
   - quit では渡す先がないので、停止の時点で届いていた分は読んでから答えます。
4. **待つのは、上限まで。**
   - 停止を伝えられてから `graceful-shutdown-timeout`（秒、既定値 10）が過ぎた世代は、残っているサーバを打ち切り、警告を出します。
   - 打ち切りは、非同期例外による cancel です。
   - quit では、それでも終わらない世代を `graceful-shutdown-timeout` ＋ 1 秒まで待ち、警告を出してプロセスを終えます。

## 層の分担

| 層 | 持つもの |
|---|---|
| `dnsext-iterative` の `DNS.Iterative.Server.Stop` | `Stopper`（停止を全サーバに伝える）、`Sessions`（セッションを数えて、全部終わるまで待つ）、`stoppableDraining`（QUIC 用） |
| `dnsext-iterative` の各サーバ | 停止を伝えられたら受け付けを止め、自分のセッションが終わるまで待ってから戻る |
| `dnsext-iterative` の Pipeline | pending の印を付けて外す。VC の受信側が、停止を伝えられた後も読み続けるかを決める（`vcStopping_`） |
| http2、http2-tls、http3 のライブラリ | HTTP/2 と HTTP/3 の GOAWAY（2 回送る処理を含む） |
| `dnsext-bowline` の `bowline.hs` | 世代を作り、ソケットを渡し、命令が quit か reload かで振る舞いを選ぶ（`udp_drain`、`vc_drain`）。上限で打ち切る |

- サーバは、停止が quit なのか reload なのかを知りません。知る必要があるときは、bowline から判定関数（`udp_drain`、`vc_drain`）として受け取ります。
- 止める処理は、各サーバが `Stopper` に登録します。`stopAll` の後に登録した処理は、その場で実行します。

## 世代の終わり方

### reload

1. 命令が来たら、全サーバに停止を伝えます（`stopAll`）。
2. モニタの終了と `stopAll` の両方を待ってから、Web API を止め、待ち受けソケットを次の世代に渡します。
3. 次の世代は、同じアドレスのソケットがあれば受け取り、無ければ bind して、すぐ受け付けます。
4. 古い世代は、裏で読んだ問い合わせに答え終えてから終わります（QUIC を除く）。
5. 次の世代が使わなかったソケットは、古い世代が全部終わってから閉じます。
6. 古いキャッシュを捨てる reload では、古い世代が終わってからキャッシュを止めます。

### quit

reload の 1〜4 と同じです（ソケットを受け取る世代はありません）。その後、全世代が終わるのを待ってから、ソケットを閉じます。

## 実装で迷ったとき

- 新しいサーバを足すときは、`Stopper` に止める処理を登録し、セッションを数えて、全部終わってから戻るようにします。
- 問い合わせに答えずに処理を終える箇所を足したら、そこで pending の印を外しているかを確かめます。
- 終わるまで待つ処理を足すときは、`graceful-shutdown-timeout` で打ち切られることを前提にします。待ちの側で別の上限を持ちません。
- quit と reload で振る舞いを変えたいときは、サーバに命令の種類を渡さず、bowline から判定関数を渡します。

## 停止したときの振る舞いの一覧

**列**

- ①：読み終えて処理中の問い合わせ
- ②：停止の前に届いているが、まだ読んでいない問い合わせ
- ③：停止後に既存の接続へ届いた問い合わせ
- ④：停止後の新しい接続や問い合わせ
- 伝え方：終わりの伝え方
- 閉じる：接続を閉じる時点
- 上限：停止してから終わるまでの時間の上限（`graceful-shutdown-timeout`、既定値 10 秒）

| トランスポート | 命令 | ① | ② | ③ | ④ | 伝え方 | 閉じる | 上限 |
|---|---|---|---|---|---|---|---|---|
| UDP | reload | ○ | ○ | − | 次 | − | 済後 | ○ |
| UDP | quit | ○ | ○ | − | 否※1 | − | 済後 | ○ |
| TCP、DoT | reload | ○ | ○ | ○ | 次 | 閉 | 済後 | ○ |
| TCP、DoT | quit | ○ | ○ | ○ | 否 | 閉 | 済後 | ○ |
| DoH、H2C | reload | ○ | ○ | ○ | 次 | 二段 | 済後 | ○ |
| DoH、H2C | quit | ○ | ○ | ○ | 否 | 二段 | 済後 | ○ |
| DoQ | reload | × | × | × | 次 | 閉 | 即閉 | ○※2 |
| DoQ | quit | ○ | ○ | ○ | 否 | 閉 | 済後 | ○ |
| H3 | reload | × | × | × | 次 | 閉 | 即閉 | ○※2 |
| H3 | quit | ○ | ○ | ○ | 否 | 二段 | 済後 | ○ |

**記号**

- ○：答える。UDP の reload の ② は、渡したソケットから次の世代が読んで答える。
- ×：答えない。CONNECTION_CLOSE を受けたクライアントが、新しい接続で送り直す。
- −：当てはまらない（UDP には接続がない）。
- 次：次の世代が受ける（reload の ④）。
- 否：受けない（quit の ④）。待ち受けをやめるので、新しい接続は張れず、UDP の問い合わせにも答えない。
- 閉：終わりを伝える手段がなく、閉じることで伝える。閉じるまでに届いたものには答える（③が○）。DoQ と H3 の reload では、CONNECTION_CLOSE をすぐ送る。
- 二段：停止したらすぐ、最大の番号の GOAWAY を送る。往復を待って（HTTP/2 は PING、HTTP/3 は PTO）、受け付けた最後の番号の GOAWAY を送る。それより後の要求は断る（HTTP/2 は REFUSED_STREAM、HTTP/3 は H3_REQUEST_REJECTED）。
- 済後：伝える前に届いたものに答え終えてから閉じる。
- 即閉：答え終えるのを待たず、すぐ閉じる。

**注**

- ※1：ただし、停止から 100 ms までに届いたものは読んで答える。UDP では停止の前後を見分けられないため、窓で区切る。
- ※2：quic は、接続が動いている間は返らない。そのため reload では、終わらない古い世代が残りうる。quit では、上限に 1 秒を足した時間でプロセスを終える。
- 上限を過ぎたら、残りは答えずに打ち切る。

**補足**

- TCP と DoT は、終わりを相手に伝える手段が閉じることしかありません。そのため、閉じるまでに届いた問い合わせには答えます。
  - 受信側は、最後に読んだ後でタイムアウトの合図を立てます。送信側が先に終わって、後から読んだ問い合わせが取り残されることはありません。
- TCP の上の DoH、H2C、DoT は、reload でも古い接続が受信を続けられるので、quit と reload で振る舞いを変えません。
- GOAWAY を 2 回送るのは、1 つ目と 2 つ目の間に届いたストリームに答えるためです（RFC 9113 Sec 6.8）。
- QUIC の接続は、待ち受けソケットを共有しています。reload ではソケットが次の世代に渡り、古い接続はもう受信できないので、答えずに閉じます。DoQ には GOAWAY が無く、QUIC にも接続全体の半閉じはありません。
  - クライアントは CONNECTION_CLOSE を受けて、新しい接続で送り直します。DNS の問い合わせは送り直しても害がないので、古い接続宛てのパケットを古い世代に回すことはしません。
- DoQ の quit では、停止後に開かれたストリームにも、閉じるまでは答えます。
